# cabinet-02（入口门框）手写重建记录

用时约 21 分钟（09:29 开始看图，09:50 交付）。其中看图和测量约 13 分钟，手写和 3 轮修改约 8 分钟。

产出（都在本目录）：

- `compare.jpg`：最终对比图，角度为斜 45°、正面、俯视；`compare_back.jpg`：从走廊一侧（斜后方）、左面、右面看的对比图。

## 1. 看到了什么

这不是柜子，而是一个**斜向的玻璃门入口**，位于走廊（深灰地毯，在 x、z 都小的一侧）和室内（米色地面）之间。门所在的平面不沿坐标轴：门头正面的法线方位角是 42.86°，朝室内（+X+Z）。

现有算法把它拟合成"悬空的斜板加一截木板"，原因有两个：
- 玻璃门扇是透明的，扫描里完全没有；
- 扫描到的面都是单层薄片。

把各个视角的图对起来看，入口由下面几部分组成（从室内看，左手边是 x 小、z 大的一头）：

1. **右侧木饰面墙**：一堵沿 z 走的木墙。
   - 位置 x≈3.22–3.33，从 z≈0.42（在这里与一道紫色横墙相接）一直到 z≈1.53。
   - 端头是**整半圆的圆头**，墙厚约 0.11，所以圆头半径约 0.055。
   - 墙从地面通到天花，天花高 2.80。
   - 扫描到的是朝 +X 的那一面，上面装有门禁读卡器（黑色读头加白色面板）。
2. **门洞**：双开玻璃门。
   - 门扇所在的线在门头后面约 0.10 处，净宽约 1.95，净高约 2.14。
   - 门扇透明，扫描里没有，所以**不建门扇**：SHAPES 没有透明材质，建出来会变成一块不透明的墙。
   - 门洞两边各有一根门框立柱。
3. **两块玻璃侧板**：门框角和两侧木饰面之间各有一块，都与门线成约 45°。
   - 右侧这块沿 x 走（z=1.406），左侧这块沿 z 走（x=1.40）。
   - 两块都向室内斜出约 0.2 米，所以门是"内凹式入口"，平面上像一个浅梯形。
4. **门头（门头横条）**：从左侧木饰面一直通到右侧木墙圆头。
   - 是一块竖直的平板，正面平整（平面残差 0.5 厘米），高度从 2.20 到天花 2.80。
   - 立面分三段：下段是深灰绿玻璃带，2.20–2.40；中段是浅色金属横条，2.40–2.60，上面装两个闭门器；上段是深灰绿上亮，2.60–2.80，上面挂着蓝色 EXIT 灯箱。
   - 右端向室内折回一小段，收口顶到木墙圆头。
5. **左侧木饰面**：面朝 +X，x≈1.44，从 z≈3.0 开始。它大部分在包围盒外，只建了进入范围的一小段，让门洞左边有个交代。

设计意图：
- 全部是直线和平面的大棱角，只有右侧木墙的端头是圆头；
- 左右两边结构对应，都是"木饰面 + 斜玻璃侧板 + 门框立柱"；
- 门头水平贯通，把两边连起来。

不属于本物件、没有建的东西：
- 右边 x>3.8 的蓝色立牌，属于 LED 大屏 cabinet-01；
- 天花板、地面上的门槛条，属于结构；
- 门扇后面几片零散的玻璃反光碎面。

关于右侧木墙"斜"的问题：扫描里这面墙下半截（y<1.15）在 x≈3.38，而且转了约 4°；上半截在 x≈3.30，沿 z 轴。在 z=0.6 处，y≈1.2 有一道约 8 厘米的台阶。左侧木饰面也是上下差 4 厘米，而两块玻璃侧板、门头都是竖直的。

判断：这是扫描两趟没对齐留下的接缝，不是真的墙歪了。所以墙建成竖直的，放在使误差最小的 x=3.33。我也试了斜一点的竖直面，误差并没有变小（3.85 对 3.83 厘米）。

这样做的代价是墙上的扫描点均距约 3.7 厘米。现有算法用逐层堆叠的截面跟着这道接缝走，所以在这一块分数更高。

## 3. 记录的组织方式

`cabinet-02.shape` 是一个 group，下面分 3 组：

1. **右侧木饰面墙**：
   - 墙体 1 件：俯视轮廓挤出，端头整半圆，用 arc，bulge=1；
   - 读卡器、白色面板各 1 件。
2. **侧板**：右侧玻璃侧板、左侧玻璃侧板、左侧木饰面，各 1 件。
3. **入口**：整组带 transform，position 为 O，yaw 42.858。
   - 门头三段：同一个 L 形俯视轮廓挤出，按高度分 3 段，各段颜色不同，浅色横条比上下两段凸出 1 厘米；
   - 门头附件：EXIT 灯箱 1 个，同款闭门器 2 个；
   - 门框立柱 2 根，同款，左右对称。

同款部件（两个闭门器、两根立柱）共用同一组尺寸。它们都是单个 box，没有单独做模板。

## 4. 每轮改了什么

偏差都取 compare 的口径，单位厘米：扫描→模型给均值 / P90 / 3 厘米内比例，模型→扫描只给均值。

| 版本 | 改动 | 扫描→模型 均值 / P90 / 3cm内 | 模型→扫描 均值 |
|---|---|---|---|
| 现有算法 | — | 2.94 / 6.90 / 80.3% | 11.03 |
| v1（初稿） | 右侧木墙（圆头）、两块玻璃侧板、左侧木饰面、门头三段、EXIT、闭门器、门框立柱 | 3.08 / 5.53 / 75.8% | 4.30 |
| v2（第 1 轮） | 门头下段向走廊一侧加深到 z=−0.10，想吃掉门洞顶部那圈底面点；左侧木饰面 x 改为 1.442 | 3.07 / 5.40 / 74.6% | 4.48 |
| v3（第 2 轮） | 门头下段的加深撤回（这个部件的均距从 2.21 变成 2.43，反而更差）。<br>发现 EXIT 和闭门器的位置是用旧坐标系的数算的，偏了 0.19，改正。<br>门框角按俯视点数重新定：门线 z≈−0.08…−0.10，门洞 x −1.10 到 0.86。<br>两块玻璃侧板相应延长到门框角 | 3.05 / 5.47 / 76.1% | 4.39 |
| v4（第 3 轮，最终） | 玻璃和门头深色段的颜色提亮，与扫描的观感一致；读卡器和面板按黑、白点的范围微调 | **3.05 / 5.47 / 76.1%** | **4.39** |

补充：去掉不属于本物件的 LED 大屏立牌后（范围收到 x≤3.73），偏差是：

| | 扫描→模型 均值 / P90 / 3cm内 |
|---|---|
| 现有算法 | 2.21 / 6.17 / 81.0% |
| 新模型 | 2.28 / 5.29 / 76.7% |

剩下的偏差主要来自两处：
- 右侧木墙的扫描接缝：约 9000 个点，均距 3.7 厘米，占总误差约 70%；
- 门洞顶部参差的玻璃边。

## 5. 结论

- **好的地方**：
  - 一眼能看出是"木饰面墙 + 斜玻璃侧板 + 门头 + EXIT 灯 + 双开门洞"的入口；
  - 门头是一条完整、水平、贯通的横条，右侧木墙是有圆头的竖直墙；
  - 结构左右对应，没有悬空的斜板；
  - 模型→扫描从 11.0 降到 4.4 厘米，多建的东西少得多；扫描→模型的 P90 从 6.9 降到 5.5。
- **差的地方**：
  - 扫描→模型的均值和 3 厘米覆盖率略逊于现有算法：3.05 对 2.94，76% 对 80%；
  - 原因是现有算法跟着扫描接缝把墙做成了上下错位的两截，而我保持墙是竖直的一整块；
  - 门扇没有建，因为是透明玻璃、扫描里没有，SHAPES 也没有透明材质。
