# 实拍对齐与漫游验收

## 把照片变成可用的对照

记录拍摄日期、来源、署名、许可及裁切信息。先确认建筑当时已建成，立面、植被或岸线与当前场景处于可比较的时期。相同照片的不同裁切只算一次观测。

用远处几个分布较开的固定地标拟合朝向、焦距和相机滚转，再用近景结构检查位置和视差。普通照片用针孔模型；拼接全景可试柱面或球面投影。GPS 和 EXIF 用作起点，记录最后的轮廓残差。遮挡、施工、极端反光和残差覆盖的边缘从采样区域扣除。若诊断相机需临时裁掉遮挡，最终交付仍用正常游览相机。

按问题选择读数。天空与立面的相对亮度适合检验灰白楼面，三角边两侧的亮度跳变适合检验法线，水面多个无船区域的分尺度对比度适合检验细浪。记录每个机位的变化方向，天气与太阳方位差异会影响绝对数值。一侧改善而另一侧恶化时，缩小材质作用范围或保留原版本。

校准一整排楼的相对亮度时，可在每张配准照片里选出多栋同屏建筑。用线性亮度计算各楼立面与实拍相差多少档，再减去这些差值的中位数，吸收整张照片的曝光差异。保留位于连续立面内部的样点，检查边缘配准误差、窗格反光和遮挡。当不同朝向的照片给出一致的偏差方向时，可先采用较小幅度校正。用另一张照片检验楼群的相对明暗次序，并单独记录偏差变大的楼。

楼体既有细窗格又显得平时，把实拍和渲染缩到相同的游玩画幅。在同一实体、朝向连续的立面内部取样。先抑制窗格尺度的明暗，比较各采样点亮度的百分位跨度，再单独比较小片窗格的反差。将实拍采样位置在配准残差范围内平移，检查判断是否随之翻转。照片之间需分别记录天气、拍摄时间与可用楼面。

在浏览器固定相机与照明，分别减弱底色贴图中成片的明暗、关闭立面的局部环境反射，看哪一项能解释全景偏差。贴图试验可用不同分辨率层级暂时调整亮度，保留清晰窗线。若两个机位的结果相反，先检查太阳方向和拍摄时楼宇的完工情况。确认问题来自素材自带的光照后，再按材质区块烘焙修正，避免相邻的屋面、石材和玻璃串色。[Unity 摄影测量去光照工具](https://github.com/Unity-Technologies/DeLightingTool) · [three.js 环境反射预过滤](https://threejs.org/docs/pages/PMREMGenerator.html)

用配准实拍测亮度时，在正常帧完成相机约束、阴影和流式更新后，用独立相机恢复照片眼位、滚转、视场与宽高比，再画基准、候选和材质识别图。核对实际投影中的地标，记录配准残差。按误差与轮廓宽度内缩选区，确认剩余像素确实来自同一表面。机位看不见目标时记录零个有效像素并跳过亮度统计。分别在照片和渲染中量取目标相对同屏天空的线性亮度比，同时记录表面内部的明暗分布。天气、曝光或源贴图拍摄时间不同的照片，保留各自的数据和适用范围。

用正射机位校验航拍时，检查流式地图是否按正射视域加载。切换到独立的诊断相机后，流式瓦片可能仍只覆盖原透视机位。测颜色前给未覆盖的地表加遮罩。怀疑正常游玩也有空洞时，从实际游览入口冻结同一帧，分别换黑白背景，将透出背景的像素沿视线投回地面，统计有效地图距离内的缺口。恢复原帧后再对照。

从高处转身时，若新露出的楼脚闪过天空色，使用实际游玩相机重放转向。在每个姿态把背景分别临时设成两种识别色，只统计随背景完整换色、且视线应在有效距离内落到地表的像素。记录每帧缺口的面积、离屏幕边缘的距离及距上次瓦片选择的时间。对同一姿态强制刷新地图，可区分未及时覆盖的地面和真正的几何缺失。单独旋转诊断相机时也要为该方向更新地图，离屏反射探针还要核对各面的瓦片与水面倒影。

瓦片预算固定时，扩大预取视野可能挤掉画面中的高分辨率地块。用斜视海岸的射线核对瓦片层级。测试按转角或投影变化提前更新时，以同路线切换前后的地面缺口、纹理精度和浏览器帧耗时选择触发条件。基准与候选都保留逐帧结果，定时更新与转身起始帧的相位会改变缺口的峰值。测试站只在屏幕边缘留下零星采样时，保留采样坐标、相机转角和距上次刷新的时长。以几个不同的刷新起始时刻回放相同转身，估算残余缺口的宽度和持续帧数。

转身时整片楼群晚出现，可以先分清瓦片是否已经下载、是否在几何缓存中、以及当前帧是否将它设为可见。沿同一相机轨迹逐帧强制选取一次瓦片，保存当前视锥需要的编号。在常规回放中只翻转同一批已驻留几何的可见性，并比较两张同帧画面。另记应在视野内但尚未载入的编号。对照中固定水面倒影与动画，避免把两次渲染之间的变化计入楼群。若小角度转身就会露出街区，实测累计转角触发选瓦片的时机，同时比较同一路线的 P95 帧间隔、请求取消量和可见几何数量。

## 临水照片的眼位与视差

同一相册的多张照片可能共享景点坐标。下载原图，按图像方向标记旋转到显示方向，记录实际解码的宽高。地理检索漏掉图片信息时，按文件页编号补查原图、拍摄日期和许可。地图上的标记可以用来缩小搜索范围。

先用一组远楼轮廓拟合相机。把另一栋横向隔开的建筑投回照片，量取左右边缘和顶部的偏移。若它也进入下一次拟合，另外保留一个可辨认的岸边地标作复核。横向相邻的多座塔楼即使都对齐，沿视线移动眼位并改变焦距也可能得到相似的轮廓。

把眼位投到有尺度的正射影像上，核对步道边沿和地面高度。对于沿堤照片，可检验岸顶折点、墙脚水线方向和近端遮挡顺序。在可步行的几段位置分别拟合，记录眼高、远楼误差和近岸的变化。多个解仍能让远楼对齐、却改变前景的水陆归属时，取各解都可见的水域和立面测色。涉及近岸建模的结论留给能约束近景的第二个视角。

## 在远景里分清墙、窗和遮挡物

一栋楼可能由测绘主体、附加窗带和阳台等多个网格组成。保留正常场景的相机、深度测试、实例变换、裁剪和透明裁切，在独立的单采样渲染目标中为实体与材质槽写入唯一编号。读取原始像素；颜色空间转换、色调映射、多重采样和后处理都可能改变编号。用前景遮挡和一处可辨认的窗框核对拾取结果。

按实际可见的材质槽统计像素数，并在相同位置读取原材质、中性灰、关闭直射的中性灰和无光照底色。显示画面开启抗锯齿时，边缘像素仍可能同时包含玻璃与墙面；用有足够内部像素的区域比较亮度。若窗框在游览距离只占亚像素，可比较整片立面的窗墙对比度，另选近一些的机位定位成因。记录哪些机位看得到目标，避免把遮挡算成零改善。

若同一栋楼转角的两面明暗突变，在实拍和渲染的两面各选一片连续的窗与墙。分别比较暗窗、整片中位亮度和浅色楼板。若一个面的窗来自独立附加网格，另一个面的窗仍画在主体贴图上，先核对两面的开间和楼层能否在照片中接续，再决定是否延续窗框与窗槽。采集局部环境反射时同时隐藏主体和附加立面，并在恢复后分别验看两种朝向。

## 复现同一段游览

- 保存相机位置、目标、视场、画幅、裁剪面、像素比、曝光和环境资源版本。按用户路线选平视步行、临边侧看和远景等有代表性的视角。用相同的轨迹、时钟和随机种子输出前后两版。
- 把配准实拍的取景点用作步行路线时，沿桥面或人行道纵向取样，用实际可行走网格核对脚下高程、边沿距离和眼高。垂直于视线平移可能越过栏杆或进入水面。逐帧检查后再用近景构件的画面占比决定优化优先级。
- 等模型、纹理、地形与矢量瓦片加载完成。核对失败数、当前相机和材质绑定。A/B 前端版本相同；若改动就在渲染器，记录两份构建的差异及共同资产版本。将基准再渲染一次，用重复图间的差异估计测试噪声。
- 保留全幅并排图和同步运动片段。局部放大用来说明差异来自哪里。观察远楼与天空的分离、细枝与栏杆的闪烁、遮挡交界、LOD 跳变和反射延迟。差分像素比例只表示影响范围，结合可见位置、持续时间及画面判断价值。

组合空间的两份公开草稿可能带入不同时刻的活动道具或演示图层。若某个本应稳定的机位突然出现大块差异，先对比两份公开快照中的实体、锚点和程序配置，再用同一组合状态重建基准。在专用于实景观感的草稿内调整演示内容时，记录所改的属性和适用范围。用普通游客入口验证天际线与倒影，再测帧耗时。

先核对常用机位能看到哪些楼。可在相同深度测试和遮挡条件下，将待评估的整批楼体分别绘成黑、白两次，用差分统计它们在全幅中的可见面积。冻结水面反射、曝光和动画。对照两岸、步行和跨湾机位，使纹理与模型的投入覆盖实际游览画面。

决定能否裁掉被遮挡的成批模型时，可先量直接可见面积，再让倒影与阴影缓冲随每次显隐重新渲染。即使地面平视时没有像素差，转身、抬高视点或走到对岸都可能露出整片轮廓。用相同路线交替测量原版与候选的帧耗时，另记实际减少的绘制调用和三角形。

检查抗锯齿时，用同一机位的多个亚像素偏移在线性光空间平均成参考图，再让相机移动一小段，为第二帧独立生成参考。对比现有输出与候选滤镜的单帧误差、两帧误差的变化和细纹对比度。在滤镜要求的色彩空间中测试，先用直通路径核对像素。单独测量后处理的耗时，并在完整场景里复测入选方案。

### 枝叶、栏杆和细钢架在缓慢移动时闪烁

锁定时钟、机位、投影和可见瓦片，生成原分辨率与双倍宽高的画面，再将两个相机投影水平移动同样的四分之一显示像素。把高分辨率图在线性光空间缩回玩家视口，比较静止帧的边缘反差和移动前后的像素变化。还原原投影再拍一次，剔除动画和加载造成的变化。页面合成、透明视频屏或镂空材质会影响截图，独立后处理前先验证复制操作在不透明像素上能重现原图。透明区域需要与实际网页背景一起比较。

用八个完整游玩机位的一次对照，FXAA 的全强度设置使清晰边缘的平均反差降到双倍采样参照的 68%–80%，原图在相同位置为 92%–102%。半强度只改善了四个机位的亚像素运动误差。单帧更柔和时，继续检查步行树冠、临水栏杆和隔水楼群的连续帧，再决定是否启用全屏处理。改变内部渲染分辨率时对齐显示尺寸，记录设备像素比和重采样方法，再用原路线测帧间隔。

## 把性能与视觉收益放在一起

在同一浏览器、设备和分辨率上预热两版，尽可能交替采样以减少负载漂移。按路线报告样本数、帧耗时中位数和 P95，同时检查绘制调用、三角形、显存占用或资源体积中与本次改动相关的项。区分首次加载与稳定帧。强制 GPU 回读会改变耗时，注明测量口径；稳定帧渲染用时与整页实际帧率分别报告。

在独立工作树中测试浏览器构建时，若 Vite 报 `Denied ID`，检查报错资源和 `node_modules` 的真实路径。共享依赖的符号链接可能把 Draco 等通过 `?url` 导入的文件解析到另一棵工作树。按锁文件在当前工作树安装依赖，或在锁文件与目标平台相同的情况下使用该目录的本地副本，再跑完整测试和类型检查。

核对测试版的场景差异时，基准和候选使用相同的读取接口。公开预览可能只提供扫描的网页模型，管理快照还会包含扫描原件和配准信息。在同版本分别核对公开快照之间、管理快照之间的字段，避免误认资产丢失。用公开预览下载本轮变更的模型并核对哈希，再从场景相机查看实际加载的模型。

需要测试版时沿项目已有入口生成预览，确认浏览器实际加载到这次的模型、贴图或着色器。流式资源超时后保存已完成机位，从失败处续跑。交付时写清可复现入口、变化最明显的视角、尚存的偏差与对照文件，并使部署范围符合本次任务授权。

发布后的验收要重新打开交付入口。有的平台会在草稿发布时撤销预览凭据，旧入口随即返回 404。需要可分享的固定版本时，从刚发布的版本创建空草稿预览，核对其基准版本和零项操作，再通过该入口实际下载新资源、切换机位、观察演出。记下预览有效期。

分批跑基准和候选时，浏览器负载变化也会进入计时。若各路线的绘制次数持平而帧耗时普遍漂移，固定相机轨迹和资源，把同一场景中的两种设置交替前后排序，分别记录相同数量的帧。GPU 同步读回得到的是一次绘制的完成时间，完整漫游的帧间隔还包含脚本、流式加载与显示调度。分别报告两种测量的条件和结果。

### 首次转身卡顿，再走一遍流畅

从新的浏览器上下文重放首次转身，再从同一起点重复一次。分别记录主视图和镜像绘制、程序数与纹理上传。嵌套的镜像绘制已经计入外层渲染耗时。若慢帧伴随新程序，按实际顶点和片元源码归组，核对两种输出目标编译出的程序。WebGL 的程序日志读取可能等待驱动完成链接，大图的首次上传也可能落在同一帧。将这些调用的耗时与不加探针的前台帧间隔并看。

预编译试验分别量启动的同步耗时、异步完成时间和实际转身的长帧。预上传贴图时，同时量单张最慢上传、被触及的纹理尺寸及数量。将像素数换算成含 mip 的未压缩体积，可以估计工作的规模；浏览器的实际显存占用需要单独测量。若后台准备本身形成可见停顿，则应把这段时间也计入玩家从入场到转身的体验。

## 核对分批上线的效果

场景数据和前端分开发版时，分别核验草稿中的资源与着色器实际绑定的资源。若需要辨别内容相似的天空或水面，使用已解码图片的源文件哈希、线性纹理尺寸或着色器参数核对。新前端到达测试站后，用同一套前端重放新旧草稿，记录完整组合的画面和开销。

当新旧前端都能读取同一张贴图时，可在模型和瓦片就绪后，从实际绘制的材质同时读取纹理绑定与新版校色参数。再从能看见目标地物的机位核对参与绘制的顶点。记录加载脚本的构建标识和每个断言的结果。若脚本先保存诊断数据再执行断言，验收结果还需包含进程退出码；首次失败的诊断文件也应保留，便于与部署完成后的游客复验对照。

对照页同时提供新旧测试版入口时，先确认平台上令牌与草稿修订的绑定方式。追加操作会使旧令牌失效的平台，可分别保存两份草稿。生成新入口后，从浏览器打开已交付的旧入口与新入口，核对两边都能载入对应的场景。

定位跨湾全景的慢帧时，分别统计主相机、镜像相机和阴影贴图实际提交的绘制次数，同一帧可能包含多个阶段。慢走和转身各测一次，对照刷新倒影、刷新阴影及两者都复用的帧。若怀疑某组模型，先在同一机位交替恢复与隐藏，记录全幅像素差、帧耗时中位数和高分位值。即使去掉数十万三角形，帧耗时也可能落在重复测量的波动范围内。

全景机位掉帧时，在浏览器中按渲染阶段、材质和对象类型统计实际绘制次数。检查座位标记等重复几何，即使屏幕上的文字已隐藏，圆点仍可能逐个绘制。形状和材质相同的静态标记可按邻近位置做实例化，让视锥能单独剔除远处的分组。回放同一路线，比较全幅像素、每帧绘制次数、提交的三角形和实际帧间隔，并验证标记的位置、点选、主题色和剖切。

演出机位和自由漫游可能使用不同的高度边界。重放演出全景时，用该机位的正常入口，记录渲染前实际的相机位置、目标与投影矩阵。对照两版时核对这些值，自由漫游入口可能会把相同输入高度截到边界上。

用户指定历史版本时，用对应的场景快照核对互动配置、节目、设备和命名机位。在同一前端重放两份快照并注明前端版本。模型和锚点齐全时，仍需比对负责启动巡演的实体属性、站点顺序和节目引用。通过用户入口依次切换机位，检查每个镜头的实际眼位、可见设备和动画，再返回自由漫游验证相机边界。草稿发布后，从已提交版本重新打开验证链接。

成组的动态物体看似消失时，先查它们是否共用同一次模型下载。遇到偶发加载失败，可在测试浏览器中让首次请求返回实际遇到的临时错误，再从发布入口验证恢复后的实例数量与运动。若实例已加载，锁定机位和动画时刻，对照新旧版的屏幕坐标。在同一帧切换这组物体的可见性，用两幅图的差分测量它们在背景前能辨认的面积，区分轨迹偏移、遮挡和背景对比度变化。

用历史照片对齐天际线时，确认相机眼位相对现有地面、水面和新建码头的高度。地标在屏幕上可以对得很准，镜头却可能埋在今天的岸墙里。这类机位只用于仍可验证的可见区域。按实体编号和当前模型重画遮罩，剔除遮挡和轮廓边缘。跨天气比较多张照片时，可先扣除每张照片中一组参照建筑的整体曝光差，再看成排立面的相对亮度误差。结合全幅图判断遮蔽或光源调整在游玩距离是否可见。

若场内屏幕或机位按钮由网页叠加绘制，另存包含界面的整页截图或录屏。检查播放器实际能否播放，并在历史版本打开同一节目源，区分外部节目失效与场景配置回归。

定位移动时的闪烁，可以固定动画时钟，在两个相邻相机姿态各保留原图、材质识别图和高分辨率参考图。将参考图按面积缩回显示尺寸，在每个姿态先求渲染误差，再看两帧误差的变化。结合材质在全景中的可见面积，区分树冠、楼群和水面各自的贡献。采用分块渲染生成参考图时，先用完整机位生成阴影与倒影，再为各块复用。拼回全幅后检查岸线、遮挡和倒影位置。

全景转身掉帧时，分别计量 GPU、WebGL 提交、标签投影和浏览器布局。即使 HTML 标签已隐藏，CSS2DRenderer 仍可能逐帧投影、排序并改写 CSS 变换，随后第一次读取屏幕边界就会触发布局。在投影前把本帧的显示资格同步给 CSS2DObject，保留参与重叠避让的候选。沿同一路线逐帧核对可见文字和屏幕位置，包含默认、展开、收起、事件提醒、悬停、聚焦、清除和切换机位后的第一帧。

用前台浏览器的 `requestAnimationFrame` 时间戳重放相同路线，按经过时间推进相机，保证慢帧时两版仍走过相同距离。预热后按 A、B、B、A 的次序交替运行。用有效帧间隔数除以这些间隔的总秒数计算 FPS，另列帧间隔 P95、主线程绘制耗时、画布像素尺寸与 GPU。将截图、同步读回和录像放在单独的回放中。某个机位两版都达到显示器刷新率时，记录 CPU 或 GPU 时间还能判断余量变化。

在流式地图中沿同一路线转身两遍，分别记录可见瓦片、完成解码并进入缓存的瓦片、被取消的请求及几何缓冲字节数。缓存接近上限时，留意同一块仍可见的数据是否反复生成后被丢弃。若压缩顶点属性，核对解码精度、全景覆盖和玻璃倒影，再用浏览器真实帧间隔检查首次经过及回程。

测试版验收分别记下已发布的前端构建、场景或草稿版本和浏览器实际加载的资源。合并通知可触发发布核验，部署完成通知可触发同路线实测；已有等待器继续使用。归档前后全幅画面与运动片段时，记录是否替换了本地资源、使用何种瓦片缓存，以及每条路线的取样帧数。对静止机位可在候选之后恢复原状态复拍一次，量出时钟、动态物件或流式加载造成的差异，再解释画面变化。

在配准照片里统计哪个材质使整片地面偏亮时，先单独隐藏透明接触阴影，再与原帧逐像素相减。接触阴影网格的包围范围可以覆盖整片公园，实际改变颜色的区域只在有透明度的纹素附近。给每个材质画识别色时保留纹理裁剪和多重采样覆盖，使用两套不同的颜色编码重画。只纳入两次都解码到同一材质的像素，另报有效面积。连续整数编号经边缘混合后可能刚好变成场景中另一件物体的编号。再用原图和恢复后的控制帧核对亮度，避免把屋顶、树影或水面误计到航片地表。

测试区域遮罩的缺图回退时，分别给场景传入未声明的资源、颠倒的坐标范围和加载失败的贴图，再在正常机位渲染。检查解析后的配置。若通用地理坐标函数把整份原始地图对象展开，已被校验器丢弃的可选项可能重新进入渲染器。让坐标函数只返回经纬度、原点与朝向，区域材质使用各自的已校验字段。用暂时移除遮罩再恢复的两帧确认基础航片可见、恢复后像素一致。

多个改动一起进入部署分支时，以测试站实际公布的构建提交为起点，核对提交祖先关系，然后在这个构建上逐项验收相应效果。某个 PR 经另一个 PR 合入时，它在平台上显示的合并提交可能没有单独的部署工作流。复用包含它的实际发布记录和同机位测试。尝试同步已合入的分支前先检查相对部署分支是否还有新增提交，避免重复开启空 PR。

## 重建后立面又变回旧材质

一栋楼经过多轮天光和图集烘焙时，每一步都记录实体 ID、输入和输出的内容哈希。按加工顺序从构建入口实际读到的版本开始解析。只有输入哈希与当前资产一致才应用这一步，再将输出交给下一步。以实体 ID 只保留最后一条记录，会使从原始测绘模型开始的完整重建跳过前置加工。

用上一版真实快照分别调用旧、新构建入口，对比两份完整操作列表。核对目标实体只出现一次且指向预期输出，逐项核对其它操作。比较 GLB 时先解析 JSON 并剔除重打包会改变的字节偏移和块长度，再按 bufferView 比较内容。最后从测试站预览读取新资产，核对浏览器实际加载的实体、资源哈希和版本。这样可以分清“模型已生成”、“下次重建会保留”和“游客当前看到”的状态。

把复验方法写入仓库 skill 后，分别运行 skill 的结构校验和所在软件包实际使用的格式检查。Markdown 表格新增一行也可能触发整张表的列宽检查。若自动合并长期挂起，从失败的具体作业取得文件名，在同一分支修正并验证。

当在线草稿加载了新地理覆盖图，完整构建却继续引用旧图时，逐字段查看坐标系、经纬度、朝向、覆盖四角和资源哈希。数据库与 JSON 往返可能让经纬度末位产生微小差异。按坐标单位选择比栅格精度小得多的容差来识别同一原点，对人工修改的覆盖配置和输入哈希仍做完整核对。用已发布快照、草稿快照和一个不同地理原点分别重建，检查重复构建的结果。

本地能显示新贴图，干净检出却缺资源时，对照清单中的内容哈希、远端 Git 树和场景实际下载的文件。工作区可能用 `assets/*` 默认忽略下载内容，再用 `!assets/文件名` 逐项纳入发布资产。如果拉取工具在文件末尾追加 `assets/`，Git 会跳过整个父目录。用 `git check-ignore -v --no-index` 分别检查一个发布文件和一个普通下载文件，修正产生规则的工具后再实际拉取、暂存和核对 Git 树。

## 旧天空重建后仍停在上一次调色

显示全景和光照探针可以分开发布。有的存档含两张贴图，有的只保存显示全景。修改空气散射、天空朝向或显示图后，从历史提交取出实际发布过的完整天空配置，分别用带探针和仅含显示图的版本走构建入口。核对输出的场景参数和资源清单，确认当前显示图、光照图都能加载。

另取主动调整过朝向、散射距离或探针的存档，逐项核对重建前后配置。只靠显示图哈希识别旧预设，会覆盖用户在同一张图上做的调光。重复重建一次，并对两张重烘图像分别计算内容哈希，可以分清差异来自照明像素、显示像素还是配置参数。

## 回放中整片水面消失，帧率突然提高

场景主体和地理底图可以先于矢量来源就绪。只看待下载数量时，索引尚未返回或来源已失败都会显示零。截帧前从目标图层读取状态、当前需要的瓦片以及实际可见的瓦片。对本来能看见水面的机位，检查水面材质及其已绘制的几何；只改材质时，逐机位比对前后两侧实际加载的瓦片编号。队列清空而可见集合为空的录像应重新录制，缺少一整层的帧率也应重新测量。

从发布后的游客入口重新打开，核实交互相机、反射、水面覆盖和原有演出。若能复现索引的短暂服务错误，用原有读取路径恢复一次，并测试拒绝访问和中途取消的行为。分别记录测试中确证的失败、复现采用的条件与线上当时能取得的网络证据。

## 切机位后诊断颜色失效

当首个机位的识别色正常，后续机位却与上一次候选相似时，逐机位拍下原始帧、零改动对照、识别色和恢复帧。分别核对对照与原始帧的差异、识别色覆盖的像素数。Three.js 可能复用同一材质已经编译的程序和 uniform 对象。临时诊断可跨机位复用同一组 uniform，或在每次替换编译回调时使用独立的程序缓存键。恢复原回调和缓存键后重新编译，再量取正常材质的浏览器开销。

比较材质时，两边显示的瓦片数可能相同而编号不同。先让路线涉及的瓦片就绪，在同一可见集合上重放视觉对照，用零强度和恢复帧量出剩余噪声。另开一次正常流式加载的浏览器回放测性能。同步截图和读回后，第一条帧间隔可能含几秒等待。为各版分别预热，进入计时段后从相邻的两个动画帧开始计时，另行记录首次编译或加载的等待。
