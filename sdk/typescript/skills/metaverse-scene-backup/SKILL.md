# 备份线上场景

## 定位入口

从用户实际打开的 URL 取得部署环境和根空间编号。工作台的 `?space=`、查看器的 `/s/` 或旧版 `/u/` 指向已发布空间，`/preview#t=` 指向具体草稿预览。一个成员的预览可以包含城市外景，组合的摆放和通道仍归根空间所有。仓库的演示夹具只适合验证查看器行为。

## 根据响应定位访问问题

- 在已连接的 Metaverse 工具中读组合，核对返回的 `id`。若工具没有空间参数，用 `nyxid mcp discover` 核对路径。连接的 OpenAPI 地址若带 `?spaceId=`，发现的工具会绑定该空间。另用 `nyxid api-key operations <Key 名称或编号>` 查看 Key 对应服务的实际 GET 规则。
- 区分当前账号的组织角色、获准使用的服务和目标空间的读取范围。账号的 `nyxid org list` 可以核对组织角色。服务端用 NyxID 签发的身份 JWT 和同一主体的组织权限判断空间访问。
- 若代理返回 `This destination cannot receive the caller's access token`，保留代理的原始错误。使用已授权 Agent Key 时，向该部署信任的 **NyxID 代理**发送 `x-api-key`，请求 `/api/v1/proxy/s/<服务>/api/v1/spaces/<根空间>/composition`。关闭自动重定向。某些 CLI 的 `proxy request` 即使用 Agent profile 也会发送 Bearer，可能触发同一 403。
- 需要将选定的 Key 授给本机时，使用独立 profile 的 `nyxid login --agent-key --no-wait --output json` 流程。用户确认后复用原请求编号执行 `login resume <编号> --once`。若集成直接读取当前 NyxID CLI 的 profile，先验证 `auth_kind` 为 `agent_key`，再于进程内读取该 profile 的 `token`。凭据仅用于受信任的 NyxID 请求，日志、快照与仓库只记结果。具体格式按已安装 CLI 核对。

## 固定版本与资源

1. 已发布的原生组合可以从查看器的 `/scene?at=` 得到同一时刻的成员版本、实例路径和摆放。使用管理读接口时，先记备份时刻，再用各空间的提交时间线选取该时刻的 seq，通过 `snapshot?seq=` 下载并核对根与成员。嵌套组合递归展开，保留每个实例的父路径、偏移、旋转、样式和连接锚点。对照根快照的成员及连接，避免混入稍后发生的修订。
2. 从快照枚举实体模型、形状及调色板纹理、扫描的网页模型和区块。需要源扫描时另取扫描原件。普通资源核对文件 SHA-256，区块使用 SDK 的解压与规范字节哈希校验。同一哈希跨成员去重，已有缓存也校验。资源齐全后再原子切换本地清单，记录来源、版本、文档哈希、字节数和仍需联网的内容。
3. 本地入口直接装载保存的版本。旧建造脚本可能用旧清单删掉线上新物件。用浏览器从组合入口检查两个成员的实际可见内容、摆放和门洞双向跳转。带演出系统时，切换原有机位并在两个时刻观察飞行物位置。区分已保存的场景、外部地图、直播和事件历史，按实际备份范围说明可回放的内容。

从备份制作增量时，先读目标环境的当前版本和待改实体的内容哈希。旧建造器即使只返回同一个环境实体，也可能顺带重新计算地面轮廓。用最新实体作为底稿，只写入已经验证的字段，按基准版本建立草稿。核对草稿中受影响的实体、锚点和区块，再把预览快照与基准做字段级比较。遇到版本冲突时，重新比较最新实体和原始意图。

模型上传后引用时出现 `unknown_asset`，从上传回执取得 `jobId`，在相同地块读取校验任务的 `status` 和 `lastError`。服务器会在收齐字节时返回内容哈希，校验通过后才登记可引用资源。若错误为 `over_limit`，用导出 GLB 的实际三角形数和当前环境的限额选择减面或空间分批，再核对新文件的哈希与校验结果。复用已创建的草稿，把通过校验的模型写入后从公开预览下载复核。
