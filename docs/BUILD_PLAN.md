# 平台建设计划（第一版）

依据：[整体设计](ARCHITECTURE.md)。本文写明第一版要交付什么、怎么分工、怎么验收、怎么部署。

## 1. 总体目标

在 chrono-cd 的 ChronoAI 组织下，部署一个可用的 chrono-metaverse 第一版：

1. **只读网站**：凭链接打开空间，查看三种视图（原始 / 优化 / 优化 + 扩展），支持剖切、时间轴回放和"现在"模式。
2. **接口服务**：
   - 公开读接口；
   - 写接口：NyxID 身份令牌校验，组织角色按 CMA 的做法判断；
   - 管理接口；
   - 分片上传、时间线提交、事件和组合。
3. **处理服务**：
   - 上传校验；
   - 扫描对齐；
   - AI 重建：结构 + 常见形状拟合，保留大棱角和弧度；
   - 体素化（可选风格）；
   - 网页用模型；
   - 定期清理。
4. **命令行与工具包**：`metaverse` 命令（init / admin / scan / pull / build / dev / shot / diff / check / push / publish / voxelize），以及建造脚本工具包。
5. **AI 接入**：OpenAPI 文档（可注册成 NyxID 服务）、建造技能说明、建造教程。
6. **部署**：
   - GitHub Actions 构建镜像推送到 ghcr.io；
   - chrono-cd 部署 web / api / worker 三个服务和 MongoDB 插件；
   - 用前厅扫描做演示数据，上线后实测。

## 2. 范围

| 做 | 暂不做（后续阶段） |
|---|---|
| 设计文档第 1–7 阶段里，单空间、事件、虚拟区、组合的完整数据模型和接口 | 对外开放（目录、配额计费、举报） |
| 时间线：提交、关键帧、按时刻回放、事件更正 | 高斯点云 |

| NyxID 身份令牌校验、组织角色查询、jti 防重放 | NyxID 侧的注册与开关（需要人工，见第 7 节） |

## 3. 代码结构

```
apps/api        接口服务（Bun + Hono + @hono/zod-openapi + MongoDB）
apps/web        只读网站（Vite + TypeScript + Three.js）
apps/worker     处理服务（Python：任务、上传校验、对齐、重建、体素化、清理）
packages/core   共用核心（类型、区块编码、哈希、回放引擎、校验、形状词表与网格生成）
packages/sdk    建造脚本工具包
packages/cli    metaverse 命令行
skills/metaverse-builder  建造技能说明
infra/          Dockerfile、chrono-cd 部署配置、本地启动脚本
.github/workflows  测试与镜像构建
```

## 4. 关键约定

- **形状词表**（`packages/core`，网站、命令行、处理服务共用）：
  - 包括 `box`（可带圆角半径、倒角）、`cylinder`、`cone`、`extrude`（轮廓可含圆弧和圆角）、`lathe`（旋转体）、`sweep`（沿路径扫掠截面，用于椅腿、扶手）、`loft`（少量截面放样）、`template`（实例化）。
  - 每个形状可以带 `transform`（位置、偏航、俯仰、翻滚，连续值）和材质（颜色或贴图资源）。
  - 处理服务输出这套 JSON，网站和命令行用同一份 TypeScript 代码生成网格。
- **鉴权**：身份令牌校验地址（JWKS）、签发方、受众、允许的服务编号都来自配置。测试和本地开发用测试密钥自签令牌，不连 NyxID。
- **数据访问**：只在 `apps/api/src/repo/` 里访问数据库；所有读写都要求传入授权凭据对象（设计 9.4）。
- **所有接口都写 `operationId`**，用小写加下划线；路径带 `/api` 前缀。

## 5. 验收标准

1. **单元测试**：`packages/core`、`apps/api`、`apps/worker`、`packages/cli` 的单元测试全部通过。
2. **端到端测试**（本地，用真实 MongoDB 进程）：
   1. 用测试令牌建组织空间；
   2. 分片上传前厅扫描；
   3. 处理服务完成对齐和 AI 重建，写入提交；
   4. 公开读接口按 seq 返回快照；
   5. 网站三种视图都能渲染（无头浏览器截图）；
   6. 时间轴能回到重建前；
   7. 写事件后"现在"模式能拉到；
   8. 命令行 `pull → build → push → publish` 能在地块内完成一次建造；
   9. 越权操作返回 403 或 404。
3. **重建质量**：前厅的家具用常见形状拟合，主要棱角和弧度都要体现；家具区域平均偏差不超过 3 厘米；生成的模型不超过 3MB。
4. **部署**：chrono-cd 上应用状态为就绪；公网能打开网站并看到前厅演示空间；公开读接口和健康检查正常。

## 6. 执行顺序

1. **基础**：仓库骨架、`packages/core`（类型、编码、回放、校验、形状网格）及测试。
2. **并行开发**：接口服务、处理服务（任务框架）、重建模块、网站、命令行与工具包、部署与文档。
3. **集成**：本地启动全部服务，跑端到端测试，修问题。
4. **审查**：安全与正确性审查，修问题。
5. **部署**：推送镜像，chrono-cd 部署，导入演示数据，上线实测。

## 7. 需要人工完成的事

以下事项需要人工操作，部署后列在进度报告里：

- **把服务注册成 NyxID 自定义服务**：需要组织管理员用 nyxid 命令行登录后操作，命令见开发教程第 9 节。注册后，AI 和命令行才能经 NyxID 写入。
- **ghcr.io 镜像设为公开**：如果首次推送的镜像是私有的，chrono-cd 拉不下来，需要在 GitHub 软件包设置里改成公开。
