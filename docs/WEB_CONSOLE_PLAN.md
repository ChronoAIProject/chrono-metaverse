# 空间聊天工作台

用户打开已有空间后持续聊天，编辑由在线 CMA worker 执行。网页提供空间发现、三维查看、对话、进度、草稿验收和明确发布；不提供人工坐标、方块或 JSON 编辑器。

## 网页流程

1. 连接 NyxID 后，自动列出当前账号的个人空间和所属组织空间；显示组织、只读/可调整状态，支持筛选和继续加载。即使尚未同意 CMA，也可查看自己的空间。
2. 通过顶栏的空间菜单选择空间，主区域铺满当前已发布版本；私有/凭链接查看的空间无需另行生成分享令牌。查看器沿用时间轴和实时 head 更新。
3. 明确启用 CMA 后，在聊天框描述变化。首次发送创建在线 worker，后续消息复用它和当前草稿。Enter 发送，Shift + Enter 换行，输入法选字不发送。
4. 网页每 2 秒串行观察准备任务、对话及当前 Responses v2 输出，显示已经产生的回复和工具执行状态。每轮可见修改后要求 worker 生成新预览，网页自动跟随最新链接；这不是逐 token 流式渲染，也不保证每个底层编辑操作立即生成场景。
5. 查看新草稿后明确要求发布；确认绑定正在显示的预览，切换到新预览必须重新确认。发布指令包含真实空间、草稿编号、rev 和 baseSeq，版本冲突不自动覆盖。
6. 按空间保留此标签页的 worker、未发送消息和请求恢复记录；切换空间不复用另一空间的任务。网络失败后只允许用户明确重试原请求；不自动重试写操作。空间菜单和聊天入口位于顶栏，聊天展开时占用左侧独立区域，场景按剩余宽度取景；收起后场景恢复满宽。1280×720（13 寸 Mac 的保守浏览器尺寸）下两者不重叠，手机改成场景在上、聊天在下。待确认请求保留最后的错误原因，并显示操作类型和请求编号。
7. 顶栏「创建空间」打开创建聊天，自动生成空间编号；用户提供 Scaniverse 分享链接或 GLB/扫描 ZIP，选择个人或有管理权限的组织，再描述需求。按编号打开和接入已有 worker 保留为次要入口。模型、执行审批、服务授权和完整环境控制仍可在 CMA 官方界面处理。关闭网页或授权不等于停止已受理任务。

## 授权与调用

```text
浏览器账号登录 ── HttpOnly 会话 + CSRF ──> Metaverse
                                           └─ 用户 OAuth → NyxID 组织查询 → 空间目录/只读查看

浏览器「连接 CMA」 → NyxID 现有 Agent Key 登录审批
                     └─ 复用当前个人/组织仅 CMA / proxy 的 Key，签发独立登录子凭据
                                      │
                               此浏览器 localStorage（按账号＋归属隔离）
                                      │ Authorization + 会话 + CSRF
                               Metaverse 固定 CMA 接口（只临时转发）
                                      │ 原 Key + 原幂等编号
                                     CMA ── 服务绑定校验 → NyxID
                                      │
                           CMA 托管的 metaverse 服务 Key
                                      │
                               NyxID → metaverse API → 资源 ACL
```

不扩大既有 `openid offline_access` scopes，不向浏览器或 worker 提供用户 OAuth 凭据。空间发现/查看和 CMA 调用分别验证当前用户与会话；CMA 还要求当前浏览器的明确同意版本。已有业务 `/api/v1/*` 仍只接受 NyxID 签名身份。

新增浏览器只读接口：`POST /api/auth/nyxid/spaces`（每页 40 条、按编号分页）；`POST /api/auth/nyxid/view/spaces/{id}` 及固定的 `head`、`snapshot`、`timeline`、`events`、`events/density`、`state` 子路径。只读中间件复用资源 ACL，校验组织归属证据；场景沿用公开查看器投影，内部锚点不随之暴露。不签发分享令牌，不更改可见性，所有响应不缓存，结束前再次核对 OAuth 授权版本。已发布的内容寻址区块/资源沿用原公开读取规则。组织列表或权限服务故障显示读取失败。

新 worker 仅申请 metaverse 业务服务，加上 CMA 必需模型/技能基线。组织编号只选择目标，不代表授权。新建聊天使用显式 `context.chat:true` 的交互约定，旧恢复请求保持原格式，避免改变同一幂等键的上游请求。先草稿后发布是任务约定；硬性禁止发布仍须 NyxID 的操作权限。复用已有 worker 不更改其服务权限。

## 验证与限制

- 覆盖个人/组织发现、分页、无归属证据和删除中的空间、角色移除、CSRF、userinfo 故障及断开期间的读取围栏。
- 覆盖连续追问复用 worker、新预览自动显示和重新确认、空间间记录隔离、明确同意、断网恢复及安全文本渲染。
- 桌面/手机浏览器检查已有空间查看器、聊天和预览；构建后按镜像摘要部署。
- 自动观察最多 120 次，终态或错误后暂停，可手动刷新；读取权限每次请求重新核验。聊天与查看器会产生相应的 NyxID/CMA 读请求，没有后台自动写入循环。
- 首次用户 OAuth 同意、CMA 的可续期环境授权及真实 worker 修改结果需用户授权后在线验收，不能由模拟测试替代。

## 从扫描或模型创建（统一目标）

```text
顶栏「创建空间」 → 左侧创建聊天（名称、归属、来源、需求）
                          │
        Scaniverse 链接 ──┼──→ CMA 创建带官方仓库的 worker
        GLB / ZIP 文件 ───┘          │
                  先准备 worker → 文件上传到该 worker → 核对回执
                                     │
                         metaverse-recon source / align / bundle
                                     │
                          metaverse bundle check / bundle push
                                     │
                         等实际任务完成 → 主视图显示草稿预览
                                     │
                           用户验收 → 同一 worker 发布
```

- 用户不用填编号、坐标、API 请求或组织密钥。只上传文件、不输入额外文字也可创建；归属默认个人，可选择当前有管理权限的组织。默认名称为「新空间」。
- 文件直接转发到 CMA 附件接口，单文件 20 MiB，允许 GLB 或 ZIP；网页不持久存储原文件或模型内容。CMA 回执必须匹配当前 worker、文件名、字节数、SHA-256 和固定附件路径。Scaniverse 由 worker 下载，不受 CMA 附件上传大小限制；只有高斯泼溅、没有网格时要求用户导出 GLB/ZIP。
- 创建 worker 固定检出包含 `metaverse-recon source` 的官方仓库提交 `d2ac32a337836d8338a5ed9b1cd7f8e8cc0429e2`，继续使用现有离线工具；metaverse 服务端不运行重建算法。工具先产出算法基线草稿，后续可在同一聊天中逐件优化。
- 文件流程按准备、上传、已提交分阶段保存原请求；刷新后不自动重试写入。上传结果未知时，用户重新选择同名、同大小、同 SHA-256 原文件，再以原幂等编号重试；成功的环境准备不重复执行。
- 创建按钮本身仅打开聊天草稿，提交后才创建 worker；202 表示任务已受理，界面不声称模型或空间已成功发布。新空间创建前显示准备提示，避免提前请求不存在的空间。
- 验证涵盖链接创建、文件无附加文字创建、上传中断后刷新恢复、原编号重试、真实 MongoDB 的同意/CSRF/大小与回执核对，以及 13 寸和手机的布局。线上 OAuth 和 CMA 可续期环境授权仍由用户首次登录时完成。


## 浏览器 Agent Key（2026-11-11）

用户要求 Agent Key 保存在浏览器，Metaverse 服务端不持久保存，优先复用已有 NyxID 能力。采用现有 Agent Key 登录审批流程：用户可选择已有且范围合适的 Key，由 NyxID 签发独立登录子凭据；不复制父 Key 原文，不轮换父 Key。子凭据继承父 Key 的实时权限，不能将宽范围父 Key 描述为只允许 CMA 的凭据。

- 优先复用本浏览器有效的登录子凭据；过期、撤销或权限不足时再由用户明确授权，不自动创建 Key 或扩大权限。需要登录审批时请求 CMA 服务和 proxy scope，审批在 NyxID 页面由用户完成。
- Key、一次性交付凭据和轮询秘密不进入任务文本、链接、日志、恢复记录或 Metaverse 数据库。浏览器中的凭据按账号隔离；退出、账号变化和撤销应正确处理。浏览器脚本可读的凭据仍受同源脚本安全影响，应使用合适期限和有限服务范围。
- 子凭据保存在单独的 `localStorage` 认证项，按账号和个人/组织归属隔离，不进入聊天恢复记录；刷新、同归属空间和新标签页先实时核验后复用。自动迁移当前标签页的旧版凭据，账号切换不会发送另一账号的 Key。过期或撤销时重新授权，暂时无法核验时保留凭据供重试。断开 CMA 仅撤销子凭据，不撤销父 Key；断开账号先撤销此账号在浏览器保存的所有子凭据。
- Metaverse 向固定的 `CMA_BASE_URL` 临时转发 Key、请求与幂等编号；先向 NyxID `/auth/agent-key/self` 实时核验个人归属和 CMA-only / proxy 权限，不回退到用户 OAuth。现有 Key 的登录子凭据继承实时父权限，网页不会把宽范围父 Key 当成窄范围凭据。
- CMA 和 NyxID 当前浏览器预检不足以直接完成跨域幂等写入和读取回执，因此保留同源固定转发。实测 NyxID 的 CMA 代理还会因连接与目录部署地址不一致返回 `cma_configuration_required`；其当前 dispatch 规则未接入附件上传。本实现使用 CMA 已有的直接 Key 服务绑定校验，不修改目录或放宽代理准入。
- 这项变更解决 CMA 调用凭据。现有组织空间目录和成员查询仍使用用户 OAuth；Agent Key 不能直接替代用户组织成员查询权限。CMA worker 自己的业务服务 Key 仍由 CMA 管理，浏览器不需要获得它。
- CMA 已有普通 Agent Key 服务绑定验证及 NyxID 签名代理命令准入能力，不再要求第三方身份 OAuth token 直接成为独立命令授权。[CMA #1638](https://github.com/ChronoAIProject/cma/issues/1638) 因本次接入无需该扩展而关闭为 not planned；不代表原始第二条消息已成功，原过滤器复现记录仍有效。独立安全问题 #1579、#1580 保留。

## 已知的连续聊天授权阻塞（2026-11-11）

用户实际首轮成功，第二轮追加消息返回 CMA 403。身份 OAuth 登录与 CMA 持久命令授权存在区别；不能以“已能创建 worker”推断同一 access token 可以提交后续消息。NyxID 第三方客户端令牌包含显式范围字段，CMA 当前独立命令过滤器会拒绝该形状。网页现改为以上明确获得 CMA 服务权限的 Agent Key 路径，不能移除 JWT 限制或扩大到所有服务来规避。

后端分别保留 `cma_command_authority_required`（网页凭据未获得命令授权）和 `cma_response_forbidden`（worker 交互权限被拒绝），前端沿用原请求恢复记录显示。只有两个固定上游错误码被映射，不透传任意 provider 诊断。后续消息拒绝日志只记 worker 编号、原请求编号、HTTP 状态和本地错误码，不记输入或凭据。

## 刷新后的授权恢复（2026-11-11）

- 用户确认曾显示“已连接 CMA”后刷新又看到授权按钮。只读核对发现一份已交付子凭据仍然活动且有使用记录；NyxID 的 GET self 不要求额外 read scope，不能据此扩大 Key 权限。未取得用户当时的浏览器请求，尚不能断言其单次故障的完整原因。
- 已交付凭据改为浏览器持久存储；账号与归属使用独立存储位。新标签页直接打开已有空间链接时，先读取空间目录确认归属，再核验对应凭据，避免按空聊天记录误选个人 CMA。
- 未交付申请仍仅保留在发起标签页的 sessionStorage，按账号与归属隔离。刷新继续原申请，沿用绝对过期时间和下一轮询时间；不延长申请期限，不重复发起授权，不自动重发业务消息。
- 浏览器审批夹具覆盖个人和组织：确认授权后刷新、切到同归属已有空间、再次刷新、新标签页直接打开空间、跨归属隔离、撤销；还覆盖批准前刷新后继续原申请。模拟审批与真实 NyxID 用户验收分别记录。
