# 第 3 章 基线、对齐和结构

这一章从拿到扫描开始，到"空间坐标定下来、结构（地面、墙、玻璃）按实测改对、逐件任务清单列好"为止。坐标约定：
单位米，y 向上；偏航 `yaw` 绕 y，0 = 正面朝 +Z，90 = 朝 +X（[SHAPES](../SHAPES.md) 第 1 节、技能说明第 4 节）。

## 3.1 工作区和取扫描

所有本地命令都在命令行工作区（`metaverse init <空间编号>` 建的目录）里运行，`metaverse-recon` 从当前目录往上找
`space.json`（`metaverse pull` 写的）定默认值：扫描 `scan/scan.zip`、变换 `scan/transform.json`、上限 `limits.json`、
网页用模型 `web/`、基线 `out/recon/`、重建包 `out/bundle/`，包的基础版本取 `space.json` 的 `{spaceId, seq}`（设计 8.4）。
**新空间也先 `metaverse pull` 一次**：只 `init` 没 `pull` 时本地工具照样认得这个工作区（找 `metaverse.json`），路径默认值
都有，但没有基础版本，打出的包推送时要 `--base latest`。工作区的 `.gitignore` 忽略 `scan/`、`work/`、`web/`、`out/`：
原始扫描不公开，不能随 `git add` 进仓库。

| 情况 | 怎么取 | 得到 |
|---|---|---|
| 已有空间，线上有扫描 | `metaverse pull --scan` | `scan/scan.zip`（分段下载，每段 64 MiB，断了再运行一次接着下）、`scan/transform.json`（线上的变换）、`limits.json` |
| 只有分享链接（不是组织成员，或线上还是瘦身前的版本） | `metaverse pull --share <链接> --assets` | 只读工作区：变换、物件、公开锚点、网页用模型和物件模型；**没有原始扫描**——用 Scaniverse 的原文件，`metaverse-recon scan-zip` 打包后哈希与线上相同（第 2.5 节） |
| 新空间，第一次重建 | `metaverse pull`（写 `space.json`、`limits.json`），再放第 2 章导出的扫描文件 | 放到 `scan/scan.zip`，`align` 自动对齐、写 `scan/transform.json`（`bundle` 要用它），再 `prepare` |

## 3.2 对齐

**已有空间不要重新对齐**。空间的坐标系在第一次发布带扫描的提交时固定（`spaces.frame`），之后扩展层的物件、锚点、
事件都挂在这个坐标系上。已有空间重建时一律用线上的变换（`scan/transform.json`，`prepare` 默认就读它），否则整个
重建层会和锚点、扩展层错开。工具上有三道保护：`align` 不覆盖 `pull` 写的线上变换（`source: "pull"`），除非加 `--force`；
`metaverse bundle push --publish` 遇到"扫描和线上相同、变换不同"的包会停下，确实要重新对齐才加 `--realign`；没带
`--publish` 时只提示，人看预览。

**首次自动对齐**（`prepare --scan <文件>` 或 `align`）：

1. 找到地面并摆平（前厅倾斜 0.094°）；
2. 按墙面法线的主方向绕竖直轴旋转，让墙和网格轴对齐（前厅转了 −61.42°）；
3. 原点放在实体区地面的一个角上。

**重扫配准**（同一空间隔一段时间再扫，`align --reference <参考扫描> --reference-transform <参考变换>`）：先按同样的方法
粗对齐（主墙的 4 个 90° 朝向都试），再和参考扫描做点云配准——只求绕竖直轴的旋转和平移，只用地面、墙这些稳定的结构，
剔除离群点。输出与 `pull` 相同格式的 `transform.json`（`{transform: [16 个数], source: "align", seq, errorCm}`）。工作区的
`scan/transform.json` 是线上的变换，配准结果先用 `--out` 写到别的文件，人看过再替换。误差超过 `--max-error-cm`（默认 3 厘米）
时命令以非 0 退出、**不写**输出文件，结果和候选写到旁边的 `*.candidate.json`，由人看过再决定（家具挪了不要紧，墙动了就要
重新想）——`prepare` 和 `bundle` 默认读 `scan/transform.json`，没确认的变换不能落到那里。

## 3.3 基线：`prepare`

```bash
metaverse-recon prepare [--hints hints.json]        # 已有空间：默认读 scan/scan.zip 和 scan/transform.json
export METAVERSE_RECON_BASE=$PWD/out/recon
cat out/recon/candidates.json
```

基线目录里有：扫描的渲染副本、变换、算法结构（`structure.json` 和投影到各平面的结构贴图）、算法物体（`objects.json`）、
**候选清单** `candidates.json`。候选清单就是逐件建模的任务清单，每件物体有：编号、类别、名称、锚点编号、包围盒、尺寸、
建议（`suggest: search` 先去模型库搜，`author` 定制件直接手写）、检索关键词建议、同款（`sameAs`，8 把会议椅只做一次）。

前厅：4 核机器约 46 秒；结构 6 个、物体 41 个、模板 2 个，地面 y = −0.0029。物体提示（`--hints`）可选，用来告诉算法
"这里是一盆绿植"之类；坐标和基线一致。

> 基线和线上的坐标一致是一切的前提：AI 写的物件坐标直接就是空间坐标，打包时不用换算。旧坐标系（`compute`）里写的东西
> 用 `metaverse-recon reframe` 换算，不要手工平移。

## 3.4 网页用模型

网站"原始"视图加载的是扫描的**网页用模型**：单个网格、内嵌贴图的 glb，两档（默认档、低细节档）。`metaverse-recon webmodel`
生成（工作区里默认写到 `web/scan-0.glb`、`web/scan-1.glb`）：接缝不裂开的减面、贴图补边（块外空白不会在缩小时被采进来）。

- 上限（`limits.json` 的 `webmodel`）：三角形 ≤ 50 万、贴图边长 ≤ 4096、全部贴图像素 ≤ 2 × 4096²、坐标保持扫描原坐标
  （绝对值 ≤ 100000 米）。现在默认档 30 万三角形，前厅约 13.4 MB。
- **扫描没变就用线上那份**（`bundle --webmodel <文件>`，文件来自 `pull --share --assets`）：哈希不变，"原始"视图与上一版
  完全相同，也不用再上传。

## 3.5 结构：按实测改正

算法结构：平面拟合找出地面、墙、玻璃，墙角吸附，墙顶统一高度，把扫描贴图投影到各平面（`uv: "planar"`）。它大体对，
但会把倒影、柱子、斜着的墙处理错。AI 物件集里写 `structure: "replace"` 时，地面、墙、玻璃用物件集里的
（`kind: "structure"` 的物件）；`"keep"` 时沿用算法结果。

**方法**：从 `out/recon/structure.json` 取出算法的结构物件，**只按实测改几何，贴图面板原样**；数都来自 `measure`
（`--vslice`、`--hslice` 截面，`--plane` 平面拟合）和按法向筛选的扫描点统计，写成脚本可重放。前厅改了三件：

| 结构 | 实测发现 | 改法 | 偏差（框内 / `assemble` 逐件） |
|---|---|---|---|
| 南面玻璃幕墙 | 幕墙不平行于 x 轴，往东逐渐外移；竖梃之间扫到的大多是倒影；原来 x 9.625 那根"竖梃"其实是墙垛 | 竖梃室内面、窗台前沿、玻璃面三类特征**共用一个斜率、各自偏移**一起最小二乘：竖梃线 z = 14.9094 + 0.02601·x（转 1.49°），窗台前沿在它前面 4.7 厘米，玻璃在它后面 20.2 厘米，残差都 ≤ 2.5 厘米；被展示柜挡住的一根竖梃按两侧间距补；删掉那根假竖梃 | 6.25 / 36% → 3.32 / 70%；3.24 → 2.39 |
| 西侧木饰面墙 | 12 米长的墙是一个稍斜的平面（扫描漂移） | 每 0.3 米取墙面中位、最小二乘 x = 1.2595 − 0.01349·z（转 −0.77°），残差均方根 1.7 厘米；起止点让开入口斜接板和幕墙 | 3.57 / 47% → 1.82 / 82%；3.55 → 1.27 |
| LOGO 墙 | 墙的一段其实是一扇落地到顶的木门（凹进 3.5 厘米） | 墙截到门边，门单独建成物件 | 3.62 → 3.16 |

几条做法：

- **截短贴图面板不挪贴图**：`planar` 投影按面板的包围盒算贴图坐标，截短会让整面贴图挪位。把截短的面板放进一个组，组上写
  同样的 `{texture, uv: "planar"}`，在原面板两端各放一个 2 毫米的定位小块（藏在面板厚度里），投影的包围盒就还是原来的
  整面。用网格生成核对过：截短后每个顶点的贴图坐标与原墙同一位置相差 < 1e-4。
- **看不见的按规律补**：被挡住的竖梃按两侧间距补，写进过程记录；不要在扫描没有的地方发明结构。
- **不追逐扫描起伏**：墙就写平，长墙只拟合一个平面；局部 3–4 厘米的起伏是扫描误差。
- **玻璃**：半透明（幕墙 `opacity` 0.45，隔断 0.3），颜色取扫描里玻璃本身的中位色；玻璃后面有窗帘的，在玻璃外侧
  10 厘米另建一道褶皱窗帘（`extrude`，褶深 5 厘米、间距 16 厘米），从室内看就不是一堵灰墙。
- **天花板不建**：网站按剖切高度切掉天花板（[整体设计](../ARCHITECTURE.md) 7.1）。

## 3.6 结构贴图

结构面板上的贴图是基线投影出来的扫描贴图。打包时它和别的贴图一样作为 `texture` 文件进重建包、按哈希引用，**所以服务端
拿到的就是本地看到的那份字节**（以前在服务端重算结构时哈希会对不上，要按编号回退；本地打包以后没有这个问题）。

投影贴图带着扫描的糊、高光和烤进去的阴影。要更清楚的地面、木饰面，按第 6 章换成扫描正交展开 + 清理的贴图，或者材质库的
贴图。

## 3.7 漏建团块怎么判断

`assemble` 列出"离任何物件都超过 5 厘米的扫描团块"（点数、范围），后面写着现有算法里和它重叠的物体编号。不是每一团都要建：

| 团块 | 判断 | 怎么认 |
|---|---|---|
| 玻璃、镜子后面成片的面 | 倒影虚像，不建 | 在玻璃面之后；俯视是斜着往外走的条带；正面能看到天花灯管、对面家具的影子 |
| 门后、墙外的面 | 房间外的东西，不建；从室内看得到的要补成墙体 | 在墙面之后；从通道、会议区方向看是否正对着它 |
| 地面上薄薄一层（高 0–8 厘米） | 地面起伏、踢脚阴影，不建 | 高度图连续、没有边界 |
| 桌下、角落的拉丝碎片 | 扫描噪声，不建 | 形状不规则、颜色是周围的混合 |
| 两趟扫描的接缝 | 不改结构 | 两片平行、相距几厘米的同一面墙 |
| 真正的物体（袋子、打印机、柱子） | **补建** | 有清楚的边界和顶面；用 `views` 出图亲自看 |

前厅最后剩 15 个团块，都是上面前五类；评审补建了打印桌、打印机、木门、两个袋子、两根柱子（第 5 章）。判断要写进过程
记录，后来的人才不会重复查。
