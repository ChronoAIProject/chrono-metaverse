# 第 5 章 多人建模与评审的组织方式

一个前厅有四五十件东西。一个 AI 会话从头做到尾，上下文会被几百张对比图塞满，后面的件越做越粗。前厅的做法是：
**按区域分组并行建模 → 合并 → 独立评审 → 确定性修正**；需要提升观感时再开一轮**精致化**，按编号整件替换。

## 5.1 怎么分组

- **按区域分，不按类别分**：同一区域的东西互相挨着（椅子推进桌下、袋子压在桌上），放在一组里才能一起查穿插、一起看人眼视角。
- **候选清单定归属**：`candidates.json` 里每件物体按包围盒划进一个区域；跨区域的件写明归哪组。每组一个工作目录。
- **结构单独一个负责人**（或合并者兼任）：地面、墙、玻璃按第 3.5 节改，各组只做物件，不动结构。

前厅第一轮的六组：

| 组 | 范围 | 典型的件 |
|---|---|---|
| 入口 | 入口门框、LED 大屏墙、入口内侧横墙 | 定制件，手写 + 烘焙 |
| 前台 | 前台、台上的显示器键盘水杯、办公椅 | 前台手写；小件找库模型 |
| 会议区 | 长会议桌、8 + 1 把会议椅、桌上的本子 | 同款椅子做模板 |
| 休息区 | 两张沙发、边几、两把休闲椅、机器人、机器狗、行李箱 | 家具先搜库 |
| 东侧隔断与柜子 | 玻璃隔断、镜面展示柜、墙垛、弧形窗 | 定制件 |
| 杂物 | 桌上和地上的袋子、背包、文件夹 | 小件，烘焙保留印刷 |

第二轮精致化只开了两组：**座椅与家具**（14 件）、**机器人与小件**（8 件）。

## 5.2 给每组的任务说明

每组一个 AI 会话，任务说明里写清：

1. 范围：负责的编号清单（`candidates.json` 的子集）和区域框；不在清单里的不碰；
2. 基线目录（`METAVERSE_RECON_BASE`）、坐标约定、技能说明 `metaverse-reconstruct`；
3. 标准：这一轮是"贴合优先"还是"写实优先"（第 4.10 节），偏差目标；
4. 交付物（5.3 节）和交付位置；
5. 相邻组的边界件怎么处理（"布袋归东侧组，袋口上的杂物归杂物组"）；
6. 不许做的：改结构、改别组的件、编造来源、用许可不允许的模型。

## 5.3 每组交什么

```
<组>/
  authored.json        本组的物件（编号沿用候选清单），单独 assemble 过、0 错误
  notes.md             过程记录：逐件的路线、候选、偏差、取舍、遗留；合并说明（交给合并者）
  compare/<编号>.jpg   每件"扫描 | 上一版 | 新版"三列（斜 45°、正面、俯视），底下一行是同一范围的偏差
  compare/eye-*.jpg    人眼视角（相机高 1.5–1.6 米）：扫描 | 替换进整份物件集后的效果
  scripts/             可重放的脚本：摆放算术（数都来自 place 和测量）、合并、对比图、穿插检查
  work/                过程文件（候选、place 的输出）
  alt/                 备选方案（比如颜色更对但没贴图的版本），写明怎么换
```

- 每件记录在 `props.group` 写组名，合并后还能追溯来源。
- **人眼视角图必不可少**：正交对比图看得出尺寸，看不出"像不像"；人眼视角才看得出颜色不对、实心块像黑柜子、门背后是空的。
- 第二轮的对比图要按**导入后的样子**画外部模型（第 4.3 节），否则看不出贴图坏了。

## 5.4 合并

合并者把各组产出按编号合成一份物件集，写成脚本（`merge.py` 一类），可重放：

| 情况 | 处理 |
|---|---|
| 两组认领同一件（编号不同、位置相同） | 同一范围、同一组相邻模型下各算"扫描→模型"，留好的；删另一个。前厅：蓝色购物袋 2.81 / 68.5% 对 3.23 / 55.7%，留杂物组的 |
| 同一编号两组都交了 | 同上，按同一范围的偏差取 |
| 某组标了"可选"的件和结构冲突（竖梃同时出现在结构和柜子组里） | 以结构为准，可选件不用 |
| 六组都没认领的件（候选清单里的两根柱子） | 合并者补建，`props.group` 写 `review` |
| 模板 | 只留被引用的；整件换成外部模型后不再被引用的模板删掉 |
| 第二轮按编号整件替换 | 以上一版为底，按编号替换；复核不过的退回上一版 |

合并后跑 `assemble`（`--structure replace` 时连结构一起），看整房对比图、逐件偏差、漏建团块（第 3.7 节），再查穿插和悬空
（第 4.6 节）。前厅合并稿发现并改了：沙发靠背伸进窗台、会议椅伸进桌脚、斜接板插进墙、袋子重叠、六处悬空、键盘低于台面、
展示柜漏了一级踏步。

## 5.5 独立评审

**评审者没有参与建模**（另开一个 AI 会话，或者人）。只看数字会漏掉观感问题，评审按这个顺序看：

1. **人眼视角**：相机高 1.5–1.6 米，覆盖每个区域和通道，前厅用了 26 个机位（入口往里、前台正面和背后、会议区、休息区、
   从南往北、东侧隔断、通道、东南角、LOGO 墙背面……）。每张"扫描 | 重建"同一相机、同一套**网站的灯光**。
2. **分区对比**：六个区各出"扫描 | 重建"对比图。
3. **数字**：每改一处重跑 `assemble` 和穿插检查。
4. **按观感影响排序列问题**，逐条写依据（哪个机位、哪个测量）。

前厅评审看到、并用确定性脚本修正的 5 处（整房 4.31 → 4.19 厘米，3 厘米内 67.0% → 68.2%）：

| # | 问题 | 改法 | 依据 |
|---|---|---|---|
| F1 | 镜面展示柜是一整块深色实心方块，几乎每个机位都看得到 | 改成玻璃展示柜：裙板、镜面、深色玻璃、内衬、两层隔板、竖框 | 侧面看到两道横隔板；截面量出玻璃位置 |
| F2 | 东侧玻璃隔断不透明，像一堵灰墙 | 玻璃改透明 0.3，外侧加褶皱窗帘 | 玻璃后 5–15 厘米的扫描点、侧视图下部的竖向褶皱 |
| F3 | 木门从通道一侧看是悬空的薄板 | 门后补楔形墙体 | 门后点分层统计、平面拟合 |
| F4 | 行李箱背后离墙 8 厘米，斜看有缝 | 背面加厚到贴墙 | 改正后的墙线 |
| F5 | 墙垛下的布袋是三块硬边薄片 | 改成圆角截面放样（软袋） | 观感（偏差差 0.1 厘米，在噪声范围内） |

查过、没有问题的也要写（穿插、悬空、朝向、比例、重复、多余物件、结构错位），后来的人才知道哪些已经看过。

**评审要注意的**：

- 工作台渲染页的灯光要和网站一致（现在已经对齐：半球光和主光都乘了 π）；用不一致的灯光判断颜色会偏暗约四成。
- 烘焙件在本地预览里只有后备的纯色时，要等烘焙出贴图（`metaverse-recon bake`）再判断。
- 修正写成脚本、在合并稿上逐条改写，合并稿留一份备份；评审修正不改外部模型记录和署名。

## 5.6 第二轮：精致化

第一轮之后，人看了网站上的效果，定了新标准："常见家具换成模型库里精致、带写实贴图的现成模型，同一类东西、尺寸大致对、
颜色深浅接近、朝向对就行，偏差其次"。这一轮这样组织：

1. **只开需要的组**（座椅与家具、机器人与小件），其余件不动；
2. 每组列出"换"和"保留"两张表，**保留也要写理由**（"库里精致的键盘都是黑色，扫描是白色，tint 调不亮"）；
3. 每件给出上一版和新版两种口径的偏差（单件对比、整房逐件），对比图三列：扫描 | 上一版 | 新版；
4. 汇总时**按导入后的样子逐件复核**：前厅有 4 件导入后坏了（贴图噪点、平铺贴图划痕），其中 2 件换候选、2 件退回手写；
5. 汇总写清整房数字和网站加载量的变化（4.19 → 4.40 厘米；按文件大小估计的加载量从约 12 MB 到约 48 MB，最重的是 8 把会议椅），
   以及遗留（姿态不同、同款沙发、古典款休闲椅），交给人决定上不上线。

## 5.7 人在哪里拍板

- 每一轮开始前：标准（贴合优先还是写实优先）、范围；
- 取舍：偏差变差换写实、姿态改变、站姿替换靠姿、加载量变大；
- 上线前：看预览链接（第 7.3 节），确认后发布。

## 5.8 过程记录的骨架

```markdown
# <组名>：<一句话目标>

坐标：<基线目录>，米，y 向上。偏差口径：<assemble 整房逐件 / compare 单件对比>。

## 一、结论
| 编号 | 是什么 | 结论（换 / 保留 / 手写） | 选的模型（库、作者、许可） |

## 二、方法（和上一轮不同的地方）

## 三、逐件
### <编号> <名称> → 《<模型标题>》
- 来源：<库> <编号>，<作者>，<许可>，<三角形数> / <贴图尺寸>
- 为什么选它；候选和偏差；摆放的数从哪来；和上一版比；图

## 四、合并说明（交给合并者）

## 五、风险和遗留
```
