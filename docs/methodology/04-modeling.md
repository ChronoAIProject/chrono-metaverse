# 第 4 章 逐件建模

每件物体走同一个循环：**看 → 量 → 搜 → 摆 → 比 → 定**。常见物件（沙发、椅子、显示器、打印机、行李箱、背包）先去
模型库找精致、带贴图的现成模型；库里没有的定制件（前台、LED 大屏墙、入口门框、玻璃隔断、嵌入柜、墙垛）手写参数
形状，再贴图。命令的完整参数见技能说明 `metaverse-reconstruct` 和[重建教程](../tutorials/reconstruct-with-ai.md)。

## 4.1 每件的循环

```bash
metaverse-recon views   --object sofa-01 --out work/sofa-01/views                 # 看：6 个角度，带米制刻度
metaverse-recon measure --object sofa-01 --heightmap 0.05:1.0 --hm-cell 0.1 \
    --out work/sofa-01/m.json                                                      # 量：尺寸、截面、高度图、颜色
metaverse-recon search  --query "beige two seat sofa" --category sofa --library objaverse \
    --limit 20 --out work/sofa-01/search                                           # 搜：看 sheet.jpg 挑候选
metaverse-recon place   --object sofa-01 --candidate work/sofa-01/search/candidates.json#17 \
    --scale axis --tint --out work/sofa-01/place                                   # 摆：输出 entity.json 和 place.jpg
metaverse-recon compare --object sofa-01 --model work/sofa-01/place/entity.json \
    --out work/sofa-01/cmp                                                         # 比：扫描 | 现有算法 | 新模型
```

- **先看再量，不靠猜**：尺寸、位置、角度都来自 `measure` 的数字（外接框、最小外接矩形的偏航、截面顶点、高度图、平面拟合）。
- **每件一个目录** `work/<编号>/`，最后 `assemble` 递归收集 `entity.json`。
- **每件写过程记录**：用了哪个库的哪个模型（或手写）、试过哪些候选、各自的偏差、为什么选它（4.11 节）。

## 4.2 先搜：常见物件找精致、带贴图的现成模型

**库和许可**：只用 Poly Haven（全部 CC0）和 Objaverse 里许可为 CC0、CC-BY 的对象；NC（不可商用）、ND（不可改）、SA（传染）
一律排除，`search` 已经过滤。Sketchfab 只在设置了 `SKETCHFAB_TOKEN`（只放环境变量）时可选，而且不在 Objaverse 镜像里的模型
不能按地址下载，打包时用不了。

**挑候选的顺序**（第二轮精致化时用户定的标准："同一类东西、尺寸大致对、颜色深浅接近、朝向对就行，先看精致写实，偏差其次"）：

1. **类别和外形**：比例、扶手、靠背、腿是不是同一类（桶形扶手椅、两人位方扶手沙发、带输稿器的一体机）；
2. **精致和写实**：有圆角、缝线、真实的贴图（布纹、皮纹、石纹），不是低模纯色块；
3. **颜色深浅**：调色 `tint` 只能把颜色调暗、调色相，**不能调亮**——实物浅色就选浅色或更浅的候选；
4. **比例**：`place --scale axis` 逐轴最多 ±15%，超过就说明不是同一类东西（圆桌等比缩到直径合适时高度差 21%，只能取折中）；
5. **体量**：物件模型上限 10 万个三角形、贴图边长 2048、贴图像素合计 4 × 2048²（`limits.json` 的 `model`）；超了打包时会减面、
   缩贴图——大面平滑的软包减面后基本不变，细节多的东西（19.6 万面的扶手椅）减到 10 万会塌成多面体、布纹拉丝；
6. **体积**：网站要下载每一个不同的导出文件（4.4 节"同一模型摆多份"）。

**库里没有的**：Poly Haven 的家具偏古典，没有机器人、现代行李箱、购物袋、显示器、打印机；Objaverse 里精致的四足机器狗几乎都是
黄色的 Spot（调不成灰色），也**没有坐姿、靠姿的人形机器人**。这些情况写进过程记录，人决定"换姿态"还是"保留手写"（前厅第二轮
把机器人、机器狗换成了站姿的库模型，扫描里它们是斜靠、趴着的）。

## 4.3 按导入后的样子看图

**最重要的一条坑**：网站上显示的不是原文件，而是本地工具 `models`（打包时由 `bundle` 调用）重新导出的物件模型。导出时：
多个网格合并、多材质合成一张贴图图集；摆放的旋转、缩放和调色烘进顶点；减到 10 万个三角形、贴图缩到 2048；节点用单位变换、
原点放在底面中心；只保留白名单里的扩展。原文件好看、导出后走样的情况前厅遇到过：

| 现象 | 原因 | 例子 |
|---|---|---|
| 整张贴图变成彩色噪点 | 多材质合成图集时贴图坐标对不上 | 圆形边几（Round Table Furniture Model）、黑皮桶椅 |
| 坐垫上黑色划痕、接缝发黑、方格压痕 | 原模型用平铺贴图，贴图坐标远超 0–1（±9.7、±65），合成图集后错位 | 两款沙发（Large 2 Seater Sofa、Sofa Aura 2） |
| 动作姿态变成 T 字 / A 字，零件飘在半空 | 带骨骼动画的模型只取绑定姿态 | 人形机器人、四条腿散开的机器狗 |
| 原本黑橙涂装变成纯色 | 多材质合并后贴图丢了 | 机器狗（Spot） |
| 外形塌成多面体 | 减面太多 | 19.6 万面的扶手椅 |

所以**挑模型、出对比图都看导出后的结果**：对候选先跑一次 `models` 导出，再拿导出的 glb 出对比图；工作台的预览如果用的是
原文件，就看不出上面这些问题。第二轮座椅组挑模型时看的是原文件，汇总复核时有 4 件因此退回或换掉（小件组按导出后的样子挑，
没出这个问题）。
带骨骼的模型在这条路线上用不了：要坐姿，网格本身必须是坐着的。

## 4.4 摆放

`place` 自动做：判断向上轴（`--up auto`），按扫描尺寸缩放（`--scale uniform|axis|none`），找偏航和位置，落地。然后人眼核对：

- **朝向坑**：
  - 偏航约定 0 = 正面朝 +Z、90 = 朝 +X。但**每个模型自己的正面方向不一样**（有的模型正面是 +X），`place` 自动选的偏航可能让它
    侧着放；看俯视图，不对就用 `--yaw <角度> --yaw-range 20` 限定重摆。
  - **贴墙家具的背面扫不到**，从背后看扫描反而像正面。朝向以高度图（`measure --heightmap`：靠背最高的一侧）和俯视图为准；
    前厅第一次就把沙发的对的朝向"纠正"反了，和网站上的原始扫描一对才发现。
  - 会议椅全部面向桌子、显示器屏幕朝人、沙发靠背朝幕墙——逐件看俯视列。
- **缩放上限**：逐轴缩放限 ±15%；超过就换候选。模型常用厘米或毫米单位（缩放 0.01、0.001 量级是正常的）；Poly Haven 是真实
  尺寸，缩放偏离 1 很多说明不是同一类东西。
- **落地**：底面落到结构地面（前厅 y = −0.003），不要悬空 2–6 厘米；放在台面上的东西落到实测的台面高度。
- **贴墙留缝**：和墙、门共面会闪烁，留 2 毫米；靠背让开窗台前沿（按窗台线算，不按目测）。
- **同一模型摆多份**：8 把会议椅用同一个模型，各自的变换。手写形状的同款写成**模板**、各处用实例（只存一份形状）。外部模型
  每个不同的"偏航 + 缩放 + 调色"组合会导出成一个文件：8 把偏航各不同就是 8 个文件（18.4 MB）；同一排统一偏航可以省下 13.8 MB。
  摆放时把偏航取整到同一个值（差 1° 以内看不出来），打包按相同参数去重导出。

## 4.5 调色

- `material.tint` 乘在模型原来的颜色上（sRGB 0–255），只能调暗、调色相；`place --tint` 按扫描颜色给出建议，提示"帮不上"时
  （差几倍亮度）就换候选。用 `measure --color 名=框` 取实物的中位色。
- **一个外部模型只有一个 tint**：整个模型一起变。休闲椅调成米色时，五星脚也成了近白色（扫描是深灰），改不了——挑候选时就要
  看"部件之间的深浅关系"对不对。
- 现在的导出代码里，纯色材质的 tint 乘在线性底色上，贴图材质乘在 sRGB 贴图上：同一个 tint 值，纯色模型显得更亮。给纯色模型
  调色时按显示出来的颜色换算（前厅的机器狗 tint [72,70,67]，显示约 sRGB [148,146,142]）。
- 模型库的模型是固有色，物件材质写 `shading: "albedo"`（打包时默认就这样写），网站完整受光；从扫描切出来的模型保持默认的
  `"baked"`（[SHAPES](../SHAPES.md) 第 3 节）。

## 4.6 穿模和悬空

整房合并后专门查一遍部件之间的穿插（评审时临时写的脚本，没有进仓库；工作台还没有这个命令，按下面的做法写）：

- 形状部件建成封闭网格；库模型表面采样约 6 万个点加全部顶点；用**广义缠绕数**判断这些点在不在别的物件的封闭部件里面，
  报告比例和最深的深度。斜边放样这种不封闭的形状用凸包代替。
- 前厅找到的：沙发靠背伸进窗台 6.7 厘米、会议椅座面伸进桌子柱脚 5.6 厘米、斜接板插进墙 1.7 厘米、两个袋子互相重叠、
  站姿机器狗碰到新沙发前沿（14% 的采样点在沙发里，最深 0.9 厘米）——逐一改掉（拆段、收小、挪 5 厘米）。
- **按实测保留的穿插**要写明：扫描里机器人就是压在软垫上（陷进 7 厘米），保留。
- 悬空和穿地：所有物件的底面和地面、台面比一遍。

## 4.7 独特物件：手写形状

候选的偏差明显比现有算法差、或者外形对不上（换了 2–3 个都不行），或者本来就是定制件，就手写 [SHAPES](../SHAPES.md) 形状。技巧：

| 东西 | 用什么 | 怎么量 |
|---|---|---|
| 斜面、折板（前台的斜面外壳） | `plate`：3–64 个共面点 + 厚度 | `measure --plane 名=框` 给法向、坡度和外接矩形的角点，直接当板的点 |
| 楔形、船头、凸的块 | `hull`：4–256 个点的凸包 | 几层截面的外轮廓点 |
| 台面、柜体、墙垛 | `extrude`：二维轮廓 + 高度，轮廓用 `arcs`（圆弧）、`fillets`（倒圆角） | `--hslice` 截面顶点 |
| 圆桌、立柱、灯 | `lathe`：轮廓绕 y 轴旋转 | `--vslice` 剖面 |
| 椅腿、扶手、管子 | `sweep`：沿路径扫掠圆或矩形截面，`smooth` 圆滑拐角 | 截面中心连线 |
| 软包、袋子（几个截面之间过渡） | `loft`：2–8 个截面放样 | 几层截面的外轮廓 |
| 盒子类 | `box` + `fillet`（圆角）/ `chamfer`（倒角） | 外接框 |
| 同款（8 把会议椅） | 模板（`kind: "template"`）+ `instance` | 量一把最完整的 |

- **保留棱角和弧度**：桌面圆角、椅子靠背弧度、沙发扶手卷边都按常见形状写，不要把一切都写成直角盒子。
- **不追逐扫描噪声**：平面就写平、对称就写对称、墙角就是直角；偏差到 2–3 厘米以后，再贴就是在拟合噪声。
- **玻璃**用 `opacity`（0–1）；**屏幕、灯箱**用 `unlit: true`；镜面现在只能用钢灰色示意（网站没有反射，第 8 章）。
- **实心块看起来不对时按结构拆开**：前厅的镜面展示柜原来是一整块深色实心方块，像一个黑色立柜；评审改成底座、裙板、北面镜面、
  西面深色玻璃（透明 0.25）、柜内深色内衬、两层玻璃隔板、三根竖框，偏差也从 3.74 降到 3.23。
- **从别的视角看得到的背面要补**：门只有 4 厘米厚、背后是空的，从通道一侧看就是悬空的薄板；按实测在门后补一块楔形墙体，
  门的偏差从 4.55 降到 2.62，相邻的墙也从 3.16 降到 2.32。
- **手写件的颜色**：纯色直接写 `color`（`measure --color` 取中位色）；要扫描里真实的颜色（木纹、印刷图案、屏幕画面）就写烘焙
  指令，或者按第 6 章做贴图（4.8 节）。

## 4.8 手写件再贴图

| 手写件的表面 | 做法（第 6 章） |
|---|---|
| 独一无二的图案：LED 屏画面、印刷的袋子、门牌、灯箱 | 烘焙：材质写 `{"bake": "planar", "color": [预览色]}`（`bake` 也可以是 `"box"`、`"cylindrical"`），打包时从扫描烘焙成贴图 |
| 有规律的材质：石材台面、木饰面、皮革、地毯 | 扫描正交展开 + 清理，或材质库的贴图，按米平铺（`tile`），固有色（`shading: "albedo"`），可加法线和粗糙度 |
| 大面纯色：墙漆、白色墙垛 | 纯色 `color`；近看太平时加一张细微的材质库贴图 |

## 4.9 署名和许可

外部模型物件的 `props.source` 是**署名**，六个字段都要：`library`（`polyhaven`、`objaverse`、`sketchfab`）、`id`、`page`（https 来源页）、
`author`、`license`（只能是 `CC0-1.0`、`CC-BY-4.0`、`CC-BY-3.0`）、`title`。它只能来自 `fetch` / `place` 的输出，**不要改、不要删**：

- 网站在场景里有 CC-BY 模型时，画面底边常驻一行简短署名，"全部来源"列出标题、作者、许可和来源页，并注明模型经过调整后重新
  导出——CC BY 要求署名和注明改动，缺了就是侵权；
- 署名是**写入方的声明**：服务端只校验格式，不核实模型是不是真的来自那里，所以责任在建模的人；
- `model` 字段（下载地址、sha256、大小）同样只能来自 `fetch` / `place`，打包时按它下载、核对哈希。

## 4.10 什么时候算做好

| 对象 | 目标 |
|---|---|
| 每件家具 | 扫描→模型均值 ≤ 3 厘米、3 厘米内 ≥ 70%，并且不比现有算法差；外形、朝向一眼对得上 |
| 定制件 | 大面平整、棱角清楚，均值 ≤ 4 厘米；漏建团块里没有成片的主体 |
| 整房 | 漏建团块只剩虚像和零碎噪声；没有悬空、穿地、穿墙 |

**写实和贴合会冲突**。第二轮把会议椅从手写模板换成精致的库模型后，单件偏差从 1.1–3.4 厘米变成 3.9–7.2 厘米（库模型更窄、
靠背更直），整房口径 2.6–3.4 厘米；按用户定的标准（写实优先：一眼是同一类椅子、材质真实）接受了这个取舍。反过来，导入后贴图坏了、
外形塌了、颜色差太多的，**退回手写**（边几、灰色会议椅）。这类取舍由人拍板，写进过程记录。

## 4.11 过程记录

每件物体的记录（汇总后存成提交的建模记录，随重建包上传、不公开）写：

- 是什么、在哪（编号、名称、包围盒）；
- 路线：库里的哪个模型（库、编号、作者、许可、三角形数、贴图尺寸），还是手写；
- 试过的候选和各自的偏差、为什么弃用（"颜色太黑、tint 调不亮""导入后贴图成噪点"）；
- 摆放的数从哪来（偏航、缩放、落地高度）；
- 和上一版比：单件对比和整房逐件两种口径的偏差；
- 遗留：外形和实物的差别、姿态不同、没扫到的部分怎么推断的。
