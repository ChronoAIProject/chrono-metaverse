# 多样式空间与多空间组合设计

## 问题背景与设计目标

旧版空间把查看模式硬编码为 `raw`、`optimized`、`extended`，重建层又只有 `shapes` 与 `blocks` 两种画法。这样同一空间无法面向不同工作目标保存多个命名样式，也无法把多个空间以异构风格组合起来。本设计把空间基底和空间样式解耦，提供「一处空间、任意多命名样式」与「多处空间、自由混搭组合」，同时把首页、空间页、组合页、预览页和工作台统一成可探索、可回放、可由人工智能驱动的产品体验。

## 一处空间、多种样式

空间基底只保存 `frame` 坐标系、`regions`/`plots`、`anchors`、`events` 及几何内容。样式层由 `SpaceStyle` 描述，包含内容投影策略 `mode`/`rebuiltStyle`、材质外观配方 `StyleLook`、`LightingPreset`、环境背景色。`raw`、`optimized`、`extended` 仍是内容层模式，样式只是对内容的命名投影。

`SpaceStyleSpec.visibleLayers` 是可选的独立图层选择：`scan` 为扫描网格，`rebuilt` 为重建层物件与区块，`ext` 为扩展层物件与区块。省略时完整保留旧 `mode` 的区域投影；显式列表显示所选完整图层，可为空列表以隐藏几何。扩展层包含实体区的改动和虚拟区内容。重建层仍按 `rebuiltStyle` 在形状与体素之间选择，扩展层不受画法切换影响。公开锚点保持可导航，锚点包围盒、虚拟区边界和取景范围按当前图层同步选择。`filterKinds` 可选取 `structure`、`object` 物件类别，同时约束锚点包围盒，不影响体素或扫描。管理写接口拒绝未知、空字符串或重复的图层及类别标识；旧文档省略字段时往返格式不变。公开空间、快照与 `OpenAPI` 均保留此契约。演示前厅的“扩展展区”与“扫描重建叠加”直接展示自定义图层组合。

显式的模式控件、`?view=` 或 `mode` 动作优先使用旧模式投影，暂时替代样式的图层列表；显式画法仅覆盖重建画法。选择命名样式、组合主题、成员样式或执行 `look` 动作会释放此前的模式与画法覆盖。同一动作序列按顺序处理，`look` 后的 `mode`、`style` 动作重新建立覆盖。扫描下载依据实际图层选择触发，支持在非原始模式中叠加扫描。

产品内置七套核心样式：`raw-scan` 原始扫描、`arch-realistic` 写实建筑、`voxel-blocks` 体素方块、`extended-full` 虚实共生、`maquette` 白模沙盘、`blueprint` 工程蓝图、`night-neon` 夜景霓虹。空间和快照都可以通过 `Space.styles` / `Snapshot.styles` 添加自定义样式，默认样式由 `defaultStyleId` 指向。

### 结构化自定义扩展

每个 `SpaceStyleSpec` 可选填 `extensions` 对象，保存策展标签、主题参数或其他约定的公开元数据。对象成员可以是嵌套对象、数组、字符串、布尔、数值或 `null`，字段名在数据库、管理接口、公开空间、时间线及预览快照、`OpenAPI` 和前端中均为 `extensions`。这些数据随公开样式投影，不能用于存放私密配置。扩展本身不执行代码，不自动修改渲染行为；消费者按约定读取所需字段，其余数据完整保留。

管理更新在进入数据库前递归校验每套样式的扩展：根对象深度为零，任一值的路径深度最多为 8；所有层级的对象成员与数组元素合计最多 256 条；紧凑 `JSON` 的总编码大小最多 16384 字节。所有键名为 1–128 个 `UTF-8` 字节，禁止空键、`.`、`$`、控制字符，以及 `__proto__`、`prototype`、`constructor`；数值必须有限，整数必须在正负 9007199254740991 以内，以保证 `MongoDB` / `BSON` 与前端 `JSON` 往返安全。越界、非法键名或非对象的扩展容器（包括显式 `null`）均以 `422` 和 `invalid_request` 拒绝；合法 `JSON` 中超出浮点表示范围的数值也返回 `422`。

核心样式字段与扩展容器严格区分：管理写请求中的未知样式字段或未知 `look` 字段会返回 `422`，拼写错误不会静默消失；自定义键应放在 `extensions` 内。存储模型仍容忍未来新增的核心字段，保留滚动更新的读取兼容性。省略扩展或传入空对象时均省略序列化字段，旧空间、旧快照与内置样式不增加空字段。样式目录仍属于空间设置，时间线及预览快照组装时携带当前目录，不额外创建几何提交。

前端按样式编号整体覆盖目录：快照目录优先于空间信息，同编号的自定义样式覆盖内置样式；扩展与所属样式一起替换，不递归混合来自不同版本的扩展键。`SpaceStyle` 和 `ViewContent` 保留同名 `extensions` 字段，省略或空对象不增加投影字段，扩展不参与 `styleLookKey` 或几何缓存。演示前厅的“品牌开放日”包含 `extensions.badge` 和结构化的 `extensions.exhibition`；画廊读取前者显示“开放日策展”，后者在场景视图中完整保留。未提供有效字符串标签时继续显示“专属”。

样式切换不重新计算几何。形状缓存按局部几何与模板复用；体素缓存按图层、分块坐标及内容哈希、区域过滤与调色板复用，同时复用正在生成的任务与几何缓冲，驱逐或关闭查看器时统一释放；材质派生缓存按 `styleLookKey` 隔离，切换样式或在组合中混搭成员样式时不会重跑网格工作线程，也不会修改共享材质。模型实例在成员级派生材质，因此同一 `GLB` 可以同时呈现白模、蓝图或霓虹外观。

`EnvironmentView` 统一拥有场景背景写入权：显式样式色优先，其次是当前可见环境的天空贴图或默认天空色，没有环境时为空。相同环境在样式、画法与时间线更新之间复用天空和地图，样式色不影响 `dataset.sky` 的加载状态，切回无背景色样式立即恢复天空。组合优先使用首个包含可见环境的成员作为环境来源，否则使用首个声明灯光或背景的成员，灯光、背景与天空均取自该成员。环境提交在网格构建代次检查后进行；天空回调同时校验环境代次与场景代次，过期工作不能修改新背景或灯光。

## 多空间组合与异构样式混搭

`Universe` 表示多个空间的组合，`themeId` 支持 `independent`（各自独立）、`gallery-day` 日光展馆、`night-district` 霓虹街区、`maquette-sandtable` 白模总览、`blueprint-atlas` 蓝图总览、`voxel-world` 方块世界。每个 `UniverseMember` 可保存 `styleId`，按以下五级级联解析：

1. 运行时单成员样式覆盖：查询参数 `memberStyles`、侧栏样式选择或带 `spaceId` 的 `look` 动作。
2. 运行时组合主题选择：查询参数 `themeId`、顶部主题按钮或不带 `spaceId` 的全局 `look` 动作。全局动作既可选组合主题，也可选命名空间样式；后者在同一层级对成员分别解析，未知样式按后续级联回退，不写入单成员覆盖。查询参数 `themeId` 同步保存这两类全局选择，后续主题按钮或全局动作直接替换它。非 `independent` 主题覆盖未设运行时成员覆盖的所有成员；显式选择 `independent` 时不施加主题映射，并跳过组合保存的主题，恢复成员保存样式或空间默认样式。
3. 成员保存的 `UniverseMember.styleId`：优先于组合保存主题。
4. 组合保存的 `UniverseView.themeId`：非 `independent` 时，仅映射未保存成员样式的成员。
5. 空间默认样式：先取 `scene.defaultStyleId`，再取 `info.defaultStyleId`，最终回退到内置默认样式 `arch-realistic`。

顶部主题按钮的激活态优先显示运行时选择，否则显示组合保存主题，均未指定时显示 `independent`。持久化主题处于激活态时，成员仍可保留其保存样式。

组合工作台提供成员空间卡片、单成员镜头聚焦与全景复位、成员独立样式实时切换、`door`/`portal`/`street` 跨空间连接跳转，以及街角相连、并排展廊、合院对望等排布预设。预设只产生位姿草案，用户仍可对成员进行旋转和 `X`/`Z` 微调。

## 产品体验与人工智能动作协议

- `Home` 是空间产品入口，展示单空间样式画廊和多空间组合能力，并保留工作台、连接页和演示夹具深链接。
- `SpacePage` 与 `PreviewPage` 在统一界面中提供样式画廊、视图模式、重建画法、剖切、锚点快速导览和时间线。
- `UniversePage` 是多空间组合工作台，顶部切换组合主题和排布预设，侧栏管理成员样式、聚焦、微调和跨空间连接。
- `WorkspacePage` 继续承载对话式改造；`viewerActions` 除 `mode`/`style` 外支持 `{ "type": "look", "styleId": "..." }`、`{ "type": "universe", "universeId": "..." }`，`look` 和 `camera.focus` 均可选填成员空间编号 `spaceId`。新会话使用指令协议版本 5；版本 1 至 4 及未指定版本的挂起请求重试保留原始指令字节。

样式编号遵循后端对象编号规则：长度为 1–128 的 `ASCII` 字母、数字、`_`、`-`、`.`，且不能以 `.` 开头。空间与组合编号继续使用原有规则。所有新动作都保持严格白名单和对象编号校验，旧动作与 `?view=raw|optimized|extended`、`?style=blocks` 链接保持兼容。
